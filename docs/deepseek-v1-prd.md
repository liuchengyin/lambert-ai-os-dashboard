# Lambert AI OS · DeepSeek V1 PRD / 开发准备

状态：待确认技术边界，**仅设计，不接入真实密钥，不修改生产业务数据**。
目标：**C 模式：自动分析 + 手动刷新**，将 AI 作为“今日参谋”，不让 AI 直接改任务。

## 0. 决策与边界

- V1 的“自动”：用户打开工作台时，**当天首次**自动生成建议；同日打开复用缓存，避免反复扣费；有显著任务变更时标记“建议待更新”，仍可手动刷新。若网站关闭，V1 **不**在后台读取浏览器数据、不定时推送。
- V1.1 才做：身份体系 + 经授权的服务端数据同步 + Vercel Cron / 调度 + 飞书推送，网站关闭仍能分析。必须经用户单独批准同步数据范围，不能假装 Vercel Cron 能读 localStorage。
- 首批接入：首页 AI 今日参谋；任务看板“AI 分析”；每日复盘暂保留后续迭代。
- AI 输出**只读建议**。不自动改任务状态、优先级、截止日期、Top 3，也不修改原始复盘内容。
- 不接入第三方聊天记录、每日记录正文、英语学习内容。将来需单独授权。

## 1. UI 位置与交互

### 1.1 总览

在今日 Top 3 上方增加紧凑的「AI 今日参谋」卡片，不改变既有四项指标和主布局：
- 顶部：AI 今日参谋｜今日已分析 09:10｜重新分析
- 内容：一句话重点（≤60字）；推荐 Top 3（任务名称、证据、下一步 5–10 分钟动作）；风险提醒（逾期/截止/项目阻塞）；可折叠“分析依据”。
- 状态：首次授权/未配置/加载中/成功/无任务/额度受限/请求失败/已缓存/数据变更待更新。
- 第一次使用需确认：将所选任务与项目字段发送至 DeepSeek API 进行分析。提供“仅本次”“以后允许”“取消”；设置中可撤回。默认不上传复盘和笔记。

### 1.2 任务看板

- 在工具栏附近增加「AI 分析任务」入口，复用相同后端分析服务。
- 任务分析建议与现有列表并存，用户自行决定是否调整；不在 AI 返回后直接调用 persistAll。
- 重新分析需要显式点击；加载中禁用按钮，防止重复计费。

## 2. 数据与存储

现有数据源（只读）：
- `localStorage['tasks']`：任务 ID、名称、状态、优先级、截止时间、项目关联、备注。
- `localStorage['projects']`：项目 ID、名称、状态、截止日期。
- `localStorage['top3_task_ids_v1']`：用户已指定的 Top 3。
- `localStorage['daily_reviews_v2']`：V1 默认不发送；将来复盘模块需独立授权。

新键：`ai_daily_insights_v1`（仅缓存 AI 建议）、`ai_consent_v1`（是否同意上传任务摘要），`ai_auto_day_v1`（当日自动分析状态）。**不覆盖任何旧键**。缓存建议只保留近 7 天、每条限制长度；存储失败也不能阻止现有工作台加载。

客户端发送前：过滤已完成的历史任务；只选最近到期/逾期/进行中及 P1/P2 的有限条数（建议最多 30）；备注可截断且默认不发送；不发送个人账号、Cookie、飞书 Token、任何 API Key、完整浏览器 localStorage。用户明确选中的 Top 3 不被模型覆盖。使用本地时区日期；避免 UTC 日期偏移。

`snapshotHash`：对标准化任务/项目快照计算摘要，用于识别建议过期；自动模式每天最多一次，手动刷新允许重新生成但受限流。网络失败时显示旧缓存并标记生成时间。

## 3. 服务端 API

`POST /api/ai-analyze`，只接受认证后的请求：
- 请求体：`{kind:'daily'|'tasks', localDate:'YYYY-MM-DD', tasks:[...], projects:[...], top3Ids:[...]}`
- 对 `kind`、数组长度、字段长度、状态枚举、日期格式、请求总字节数做校验；丢弃未授权字段。服务端不得信任客户端提供的系统提示词、模型名、API URL 或 token。
- 服务器用 `process.env.DEEPSEEK_API_KEY` 调用 `https://api.deepseek.com/chat/completions`；默认模型 `deepseek-flash`（可由**服务端**环境变量覆盖）。
- 设置 `response_format:{type:'json_object'}`，提示词要求 JSON 并提供示例。解析后再次验证结构；仅接受输入任务 ID 的引用，剔除虚构 ID；限制文本长度；禁止将 AI 内容当 HTML 执行。
- 输出建议结构：`{summary:string, focus:[{taskId,why,nextAction}], alerts:[{taskId?,severity,reason}], observations:[string], generatedAt:string}`。
- 失败时返回无敏感信息的错误码；不在日志中记录原始任务文本、密钥或完整模型响应；服务端超时并处理 429/5xx，不盲目重试。

## 4. API Key 与访问控制：上线硬门槛

- Key **只**放在 Vercel 的环境变量 `DEEPSEEK_API_KEY`；不进 GitHub、网页、localStorage、查询参数或截图；在 Preview/Production 分别配置。
- **当前工作台是可公开访问的静态站点，不等于具备登录保护。** 仅把 Key 放服务端**不足以安全上线**，因为公开 `/api/ai-analyze` 会被陌生人刷额度。
- V1 增加服务端鉴权（个人专用登录 + HttpOnly/Secure/SameSite Cookie 会话，或等效的 Vercel 访问保护），**鉴权覆盖 AI 接口**。登录失败次数需有持久化限制；不要把静态口令或会话签名密钥放客户端。
- 增加**服务端持久化限流**（如 Upstash Redis / 受控 KV）：按认证主体每日次数上限、短时冷却、并发上限；配合 DeepSeek 控制台额度/余额告警。不能只用浏览器 localStorage 限流。
- 无鉴权或限流时，生产 AI API 默认禁用，返回安全的 `not_configured`；不能“先公开试用”。
- 服务端强制 `POST`、限制 body 大小和请求超时；不允许调用方指定任意外部 URL。

## 5. 数据安全与回滚

1. 发布前先导出/备份现有 `tasks`、`projects`、`top3_task_ids_v1`、`daily_reviews_v2` 等数据（在用户当前浏览器内执行，避免跨设备假备份）。
2. 不触碰既有模块的写入逻辑，不迁移数据库，不更改旧 key。
3. AI 缓存独立命名空间；停用 AI 或回滚脚本后，原任务/复盘仍正常。
4. 建立开发分支 + Vercel Preview；测试通过且用户验收后再合并 main。
5. 开关 `AI_ENABLED` 默认为关闭；缺失密钥、鉴权或限流配置时接口 fail-closed。
6. 用户可清除**仅 AI 缓存**，不清理原始业务数据。

## 6. 开发任务分解（三级）

| 目的（L1） | 任务（L2） | 执行细分（L3） | 验收 |
|---|---|---|---|
| 安全调用 | API 密钥 | Vercel 环境变量，服务端代理，错误脱敏 | 浏览器源码与响应无密钥 |
| 安全调用 | 身份认证 | 个人登录/会话校验、接口鉴权 | 未登录请求 401，不能计费 |
| 安全调用 | 防刷费用 | 持久限流、并发锁、每日配额、模型超时 | 超额请求不触发 DeepSeek |
| 数据完整 | 数据快照 | 只读读取既有 keys、字段白名单、截断 | 不改变任何原始 key |
| 数据完整 | AI 缓存 | 每日缓存、快照 hash、失败回退 | 断网/失败不丢业务数据 |
| 智能分析 | 提示词 | 证据优先、3 件事、5–10 分钟动作 | 不编造任务、只读建议 |
| 智能分析 | JSON 协议 | 结构校验、ID 校验、XSS 防护 | 恶意输入安全显示 |
| 页面体验 | 首页卡片 | 自动触发、时间、刷新、状态提示 | 同日重复进入不重复调用 |
| 页面体验 | 任务入口 | 任务页按钮复用结果 | 手动刷新可用，不写任务 |
| 质量交付 | 测试与预览 | API mock、权限、限流、回归、移动端 | 测试全绿、正式版未受影响 |

## 7. 最小验收场景

- 未配置 Key / 关闭开关：原工作台正常；AI 友好提示，不触发外部调用。
- 未认证 / 超额 / 连续点击：均不能导致不受控计费。
- 第一次同意后首次打开：分析一次；当天重复打开：读取缓存；点击刷新：再次调用且受限流。
- 任务为空：展示“先添加任务”，不编造任务。
- 返回未知任务 ID、脚本标签、非 JSON、超时、429：安全降级，原任务不变。
- 不同浏览器/设备：不承诺同步缓存或任务；V1.1 才设计账号与云端同步。
- 全模块回归：总览、项目、任务、复盘、记录、阅读、英语、常用链接、设置、侧边栏展开/收起均可用。

## 8. 下一步待用户确认

**自动模式定义**：V1 先采用“打开网页后每日自动分析 + 手动刷新”；如果必须“关闭网页后也能每天自动分析并推送”，应先单独规划 V1.1 的账号、加密同步、持久存储和定时任务，取得授权后再开发。

**密钥配置**：用户自行在 DeepSeek 开放平台创建 API Key 并在 Vercel 后台设置 `DEEPSEEK_API_KEY`；不在聊天中发送密钥。

**访问保护**：确定采用个人账号/密码会话或其他正式鉴权方案。没有完成鉴权与服务端限流之前不启用生产 API。
