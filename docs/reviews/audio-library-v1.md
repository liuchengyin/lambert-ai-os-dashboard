英语音频学习第一阶段（开发验收稿）

在现有 Supabase 账号下新增私有音频集，网页与 Android 共用音频集、标题、排序、备注和续听记录。原视频模块、旧本机音频、任务数据和登录同步保留。分支 `feat/english-audio-library-v1`，基于 main `a606769`；不合并、不发布生产。

实现范围：

- 音频集列表、音频集详情、当前音频学习页；创建、改名、改标题、上下排序。
- 每集200条，分批多文件/拖放导入，自然数字排序、内容摘要去重、串行持久队列、失败重试、丢失文件时重新选择并验证摘要。
- HTTPS链接须能跨域下载且通过媒体验证才转存；失败明确提示下载原文件后导入。Android 的外部网络白名单仍受限，第三方链接可能无法转存。
- 播放/暂停、拖动、同时提供回退3秒与7秒、上一条/下一条、五档倍速、顺序播放/单曲循环、断点续听。网页单播放器；Android 使用 Media3 服务和媒体会话。
- 独立备注自动保存，IndexedDB 草稿先于网络写入，磁盘失败时仅文本使用应急存储；云端版本冲突保留提交副本并要求选择。播放进度5秒本机、15秒云端，暂停/切换补存；进度分歧可选择。
- 原本机音频入口保留，不自动迁移上传、不清空旧 localStorage。音频文件不写 localStorage。
- AI字幕折叠卡片仅预留手动入口，本轮不调用识别服务。

云存储方案与上线前条件：

- 复用现有 Supabase，新增独立三表、七个 RPC 与私有 `lambert-audio-private` bucket，不修改任务/项目/复盘表。
- 初始代码限制每文件25 MiB、每用户500 MiB、每集200条；保留的上传占位也计入容量，不能靠未完成上传绕过限额。旧本机音频仍沿用旧限制。
- 未读取到账户账单/套餐与剩余容量，以上为应用配额，不代表现有免费套餐足以承载所有用户。未购买任何服务。
- 上传使用用户 JWT 与公开 publishable key，RLS 限本人路径；完成后验证云对象大小并确认状态才显示成功。客户端不持有 service-role 密钥。
- `supabase/migrations/202610240001_audio_library.sql` 已在本机 PostgreSQL 兼容测试中执行，**尚未应用到真实项目**。需在受控测试 Supabase 应用迁移并实际验证 Storage 上传授权、两个真实账号隔离、续签和多设备冲突后，才能验收云端可用。缺少迁移时界面明确提示，不能假称已上线。
- SQL 兼容 Storage 上传预检的 `contentLength` 与最终对象的 `size`，最终确认仍必须匹配实际 `size`。依据 Supabase Storage uploader 的预检/完成两阶段流程；实际托管版本仍需验证。
- 本轮无删除接口和删除按钮，不会因导入、改名或排序删除备注/录音。遗留失败占位的回收和缓存清理留给独立管理流程，不能静默删除原文件。

Android：

- 现有项目为 Java Activity + WebView。新增 Media3 原生服务，单独媒体会话供锁屏控制，音频焦点和耳机断开处理由原生播放器负责。
- 桥接只允许固定 appassets 来源的主页面；原视频 iframe 无原生播放控制权。只接收本人路径的 Supabase 私有签名地址，不持久化签名链接或密钥。
- 系统文件选择器用 SAF，不申请广泛存储权限；麦克风权限/跟读录音属于第二阶段，本轮不申请。
- 原生版本18、0.2.0-audio-test，需要新 APK；页面更新最低原生版本18，旧壳不会尝试加载不支持的新资源目录。
- 后台、锁屏、系统播放键、音频焦点中断、耳机断开正在真实 Android 模拟器验收；网页测试不替代这些结果。真机厂商电池策略、实际来电、蓝牙设备仍需验收。
- 离线下载和缓存管理属于第二阶段，当前不把私有签名地址当成永久离线音频。

验证台账：

- SQL：账号隔离、200条、500 MiB、预检/最终大小、备注冲突副本及幂等、改名排序关联、进度版本冲突通过。
- 队列：9项通过，含第201条、自然排序、同批/并发重复、顺序上传、文件恢复和摘要校验。
- 云适配器：2项通过，含账号钉住、文件确认和重试不覆盖。
- 浏览器：3/7秒累计回退及暂停状态、播放状态、倍速、循环、独立备注、失败草稿、并发编辑、恢复重试、自然导入排序和重复导入、320/390/768布局通过（托管服务为 mock）。
- IndexedDB：旧确认不清除新草稿、应急文本回退与账号隔离通过。
- 现有账号/飞书单元14项、账号/任务多客户端同步浏览器回归、移动端任务交互与界面一致性、原视频学习完整回归通过。
- Android 构建/模拟器结果、最终提交、Preview 和 PR 链接在最终验收记录补充，不能把待测项标为通过。
