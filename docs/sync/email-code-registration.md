# 邮箱验证码注册

仅修改账号表单和共用认证适配层，不改变已有数据、同步和归档规则。

## 必须先配置邮件
Supabase → Authentication → Emails → Confirm signup：邮件正文需要 `{{ .Token }}`。保持 Confirm email 开启。不要改 Magic Link 或关闭邮箱确认来绕过。

建议邮件主题：Lambert 注册验证码

正文：
```html
<h2>验证你的邮箱</h2>
<p>你的 Lambert 注册验证码：</p>
<p style="font-size:28px;letter-spacing:5px;font-weight:bold">{{ .Token }}</p>
<p>请回到注册页面，输入验证码并设置密码。若非本人操作，请忽略此邮件。</p>
```

默认邮件服务仍受收件人与发信频率限制；真实收信需账号本人验收。

## 验收
邮箱 → 发送验证码 → 输入验证码和至少8位密码 → 完成注册 → 返回登录且保留邮箱 → 用邮箱密码登录。错码不设置密码、不切换工作台；密码更新失败可重试。注册临时会话不落盘、不启用同步。已有已确认账号通过 signup 不会被此流程重新设置密码，应使用登录/找回密码。

## 测试
29 项 Node 测试通过。浏览器使用官方 SDK 对模拟 Auth 服务测试，不能代替真实邮件送达验收。数据库迁移不变。

## Flash 审查
DeepSeek Flash 单次审查：输入6298、输出834、总7132 tokens。采纳显式拒绝已确认邮箱/防枚举空 identities 的建议。未采纳每次密码更新失败后重验已经消费的 OTP：独立内存会话已证明邮箱所有权，允许同一会话重试密码更新并非验证码绕过，SDK 仍验证有效会话。浏览器回归验证注册完成后主账号未登录，然后使用密码登录成功。
