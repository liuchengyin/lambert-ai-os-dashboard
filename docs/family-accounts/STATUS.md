# 独立账号第一阶段：访问入口与隔离核查

## 当前结论

用户已明确：关闭 VPN 时网页本身无法打开。首先阻塞的是网站入口；不能把故障直接归为 Supabase，也不能以海外执行环境请求成功证明国内可用。

现有 main 已支持邮箱验证码注册、密码登录，任务/项目/复盘通过用户 ID、本地缓存命名空间、服务端 RLS 与固定用户 token 隔离。不是从零重建账号。

阅读笔记、书签和音频不在当前 shared-sync DATA_KEYS 内，有直接使用 localStorage 的代码。未经单独改造与验收，不得称整个工作台已经适合多人共用设备或所有模块支持跨设备账号同步。家庭共享空间不在本阶段。

## 本次交付

- 可选同站账号网络通道：浏览器仅访问本站 API，由服务端向固定 Supabase 项目转发认证与任务同步请求。继续使用公开 key + 当前用户 token，不使用 service_role，不接收调用方指定主机。
- 通过现有 /api/account-config 路径转发，保持现有 Android 网络白名单兼容；不改变 SDK URL 或会话存储键，避免切通道时丢登录态。
- 默认关闭。仅在预览后端设置 LAMBERT_ACCOUNT_TRANSPORT=relay 启用；删除该环境变量并重新部署可回退。不要直接在正式环境试开。
- 网络诊断脚本：在故障网络运行 `node scripts/check-account-network.mjs https://工作台域名`。仅检查网页、公开配置和认证健康，不发送登录密码、访问令牌或私人数据。
- DeepSeek Flash 提供 A/B token 隔离测试草稿；人工核实、修正导入及测试数据后运行通过。成功调用输入1773、输出428、合计2201 tokens。首次草稿截断，usage未从日志取得，不并入已知成功量，不视作0。

## 访问入口执行顺序

1. 检查现有自定义域名及部署配置。当前 Vercel 连接返回团队访问 403，需要用户授权该团队后继续查看。
2. 如果有用户自有域名，先用独立子域名作为预览入口，验证 DNS、HTTPS、页面及 API。自定义域名并不保证国内访问质量，必须用户关 VPN 后以 Wi-Fi 和移动网络实测。
3. 域名入口仍无法稳定直连时，评估可直连的托管入口，连同 API 一起部署。不能只搬静态页面而保留不可达的账号入口。服务器/域名采购及新账户配置需要用户提供现有资源或明确选择；不自动购买。
4. 入口可达后，在预览环境试开 relay，对邮箱注册、验证码、密码登录、会话续期、找回密码与数据同步做真实联调。SMTP 配额、邮件确认配置不由代码测试证明。
5. 两个测试账号验证：相同任务ID互不可见、账号切换不串数据、退出保留待上传数据、复盘不共享。再继续其他个人模块的隔离。
6. 家人首登使用“云端工作台”，不要把当前设备上的个人访客数据自动导入家人账号。

## 验证边界

已通过40项本地mock/数据库规则测试（包含DeepSeek草稿采用后的测试）；还没有国内无VPN验收、真实双账号生产验收或全模块隔离验收。未合并、未发布正式版。
