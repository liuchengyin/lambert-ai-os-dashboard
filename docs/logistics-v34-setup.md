# Lambert OS 物流知识库 V3.4｜海陆空干线与前置配置

## 目标与设计
- 将「干」类型的大模块明确分为 **陆运／海运／空运**，保留原有「陆运干线」操作与历史记录。
- L2 大模块与 L3 子环节都可配置「前置配置」：名称、实际配置值、说明，以及前置条件/关联记录的角色。
- 例如中心计划发往「嘉兴南湖机场」，可在空运模块的「机场管理」中填写该机场作为研究中的目标，并对关联配置作备注。**系统不自动断言该机场的真实启用状态或航线配置。**
- 空运参考取自用户提供的空运管理截图：**机场管理、航司管理、航线管理、航班管理、板型管理**，另将**航班日志**单独归为「关联记录」（不是发货前必然完成的配置）。
- 海运参考：港口管理、船公司、海运航线、船期/航次；陆运参考：运输线路、承运车队、车辆与车次。全部是模板而非已核实业务规范，可单项删除／添加。
- 所有参考模板字段的实际值初始均为空，显示「待配置」，不会造数据。

## 操作
1. 先点击「解锁编辑」；
2. 干线类型栏可快捷创建「陆运干线」「海运干线」「空运干线」；
3. 大模块标题上的「前置配置」可编辑 L2 条目；中模块标题上的「前置配置」可编辑 L3 条目；
4. 支持新增/删除配置项、套用运输类型参考项、编辑配置值和说明，保存后进入**草稿**；
5. 原来的「保存草稿」和「确认发布」之后，新内容才会出现在 A/B 全链路总览；发布时保留历史回滚。

## 数据安全
- 旧数据模型仍是 schema:1，增量采用模块可选 `transportMode` 与模块/子环节可选 `prerequisites`。
- 不修改已有节点 ID、触发结果、事件码占位、分支、异常连线或其他 OS 任务项目复盘。
- 预览域名单独存储，未主动操作前不会写 V1 或版本键。
- 干线类型只负责流程分类和配置辅助，不宣称实际接入机场/航司/航线/航班/板型管理接口。
