# 独立账号第一阶段

## 本次范围

复用现有邮箱注册、登录和用户ID。本次不开发家庭共享空间，不改动VPN/域名/账号网络转发方案（PR #64独立保留）。

- 任务、项目、复盘继续使用现有按账号缓存与行级权限。
- 阅读工作区、独立阅读卡、常用书签和个人书签接入同一版本化同步队列。按文档整体处理并发冲突，保留两端版本，用户选择后再继续同步。
- 其他页面私有数据（学习进度、AI页面缓存、导航偏好等）按账号分区保存；不宣称全部都已云同步。
- 音频IndexedDB按账号分库；旧数据库保留为访客资料，不自动分配给任何家人。音频二进制本轮仅本机，不实现云上传、云录音或云共享。
- 切换账号后，旧页面的私有存储读写及音频事务会拒绝；跨标签页切换触发刷新。
- 账号默认备份只含本账号内容，不附带原访客资料或其他账号内容。主动导入旧数据需要预览并勾选确认。
- 浏览器插件的设备共享摘录不再自动写入已登录账号；显式导入仍通过当前页面保存流程。

## 首次启用与原数据

家人注册自己的邮箱，登录后选择“使用云端工作台”，默认没有创建者的私人任务、笔记或音频。创建者需要搬入原访客阅读/书签时，在自己的账户中选择“检查并导入本机数据”，核对邮箱、记录数量和冲突。不会自动把旧资料导入每个新账号。

## 数据库前置步骤（发布前必须执行）

在现有Supabase项目的SQL Editor执行 `supabase/migrations/202610270001_personal_documents.sql`。它给lambert_items扩充documents类型，并更新原有RPC的类型白名单；保留用户身份、RLS、数据、版本号及mutation ID。不要执行初始化建表脚本，也不要清空任何表。

本次没有生产数据库管理连接，因此未执行生产SQL；发布前必须确认此步骤，否则新增文档会留在本地队列、云端拒绝新增类型。旧任务同步和数据不应通过清空来解决。

回退页面前，应先确保待上传队列已备份。数据库可保留新增类型与记录，不需要删行或收窄约束。旧版本页面不展示documents，但数据仍在。

## 验证

- 43项账号/数据单元与PostgreSQL规则测试通过，包含新迁移保留任务、A/B独立文档、拒绝任意文档键、禁止直接更新表。
- 浏览器真实IndexedDB检查通过：A/B笔记、学习进度和音频Blob隔离，旧账号音频保存被拦截，旧访客数据保留。
- 真实Supabase SDK + 模拟后端回归通过：注册、登录、退出、密码恢复、离线队列、任务复盘同步及阅读/书签从网页到APP页面同步。
- App静态资源打包与云更新包构建通过。未编译新APK，未做Android真机验收；这些改动不新增原生权限。
- 没有真实生产双账号验收，也没有在生产应用SQL。模拟后端成功不是正式云同步已上线。

## 边界

同一浏览器内的账号分区不是对掌握本机开发者工具的人的加密保护。共享设备应使用各自浏览器/系统用户，妥善退出。云端权限由身份校验和RLS负责。

AI服务和飞书授权继续沿用现有服务级配置与权限，不自动把创建者的AI入口密码或飞书权限授予家人。后续若需每人独立的第三方连接与消费配额，应另行实现。
