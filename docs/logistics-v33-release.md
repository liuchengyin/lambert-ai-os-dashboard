# Lambert OS 物流知识库 V3.3｜操作简化、触发结果与柔和视觉
## 本次范围（独立 Preview，未合并正式 OS）
- **视觉**：L3 中模块（到车、收入、分拣、发出等）改为浅紫、浅蓝、浅绿、浅暖橙轮换的柔和浅色背景；中模块和大模块的黑色重阴影替换为细腻紫色投影；按钮和选中态改为温和的紫色。红色虚线继续表示异常，蓝色线继续表示条件分支；保留现有的自定义大、中、小模块颜色。
- **编辑简化**：小操作块详情保留“编辑名称／编辑内容／删除”，编辑内容缩减为操作名称、操作说明、结构化触发结果（多条，可动态增加删除）、可选备注和标签。颜色收在“外观”折叠项，轨迹编码收在“轨迹事件码”折叠项。移除「动作类型、核实状态、证据、数据字段、原信息流文本」的常规编辑/卡片显示。
- **事件数据模型**：新增 `node.triggers:[{id,description}]`，一个操作有多个事件/状态触发结果。新操作必须至少填写一个非空触发结果；旧操作可渐进式补充，避免因没有真实事件码被迫填写虚假映射。
- **码表搜索**：用户尚未发送真实事件码表，当前显示“码表待导入”的搜索入口并禁用，不构造测试码或强行把 OperationCode、原始事件码、标准轨迹码等价。旧 `operationCodes` 字段原封保存并在只读区域显示；导入真实码表后再启用下拉、联动轨迹描述。
- **业务关系**：数据看板、任务看板、结算规则不再作为每个操作表单的必填字段；未来基于真实事件和时间语义单独建模。
- **数据安全**：新增的 `logistics-trigger-v33.js` 是纯函数，新建时验证节点 id、所属子环节和触发内容。更新时仅修改 `title`、`action`、`note`、`tags`、`color`、`triggers`。不改变旧 `kind`、`information`、`data`、`confidence`、`evidence`、`operationCodes`、`eventRefs`、`branchOnly`、`stageId`、节点 id、条件分支和异常分支。采用既有“默认锁定→保存草稿→确认发布→历史回滚”，不覆写旧 V1 知识库或 OS 任务项目复盘数据。
