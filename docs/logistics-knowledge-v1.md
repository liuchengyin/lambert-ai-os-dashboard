# Lambert OS · 物流知识库 V1（工具区）

## 设计目的
以**操作节点**为学习底座，从同一业务动作出发看：
1. 操作流：谁执行什么、作用于哪些物流对象、动作完成的判定；
2. 信息流：哪些系统动作/事件/API/EDI 映射可能被触发；
3. 数据流：什么业务数据字段被记录、什么时间可作为指标输入。

当前 V1 选择“两 Tab”：**业务链路（操作＋信息）**、**数据关系**。不创建独立第二大脑。

## V1 能做什么
- 工具区「物流知识库」，支持 `?view=logistics` 直达和刷新恢复；
- 中国→哈萨克斯坦陆运作为**研究模板，不代表线上真实完整操作顺序**；
- 五个默认线路模块：国内头程、出口关务、陆运干线、进口关务、海外尾程（四类环节，其中关务拆为出口与进口）；
- 模块可上下排序、启用/关闭、添加新模块；关闭不会删除数据；
- 点击操作节点，显示业务动作、信息触发、数据记录、核实证据；
- 添加/编辑操作，更新状态（待核实／部分核实／已核实）；数据 Tab 可返回操作；
- 一键导出独立 JSON 备份。

## 数据安全与边界
- 唯一新增浏览器数据键：`lambert_logistics_knowledge_v1`；
- 读取/保存优先走 `LambertPrivateStorage`，登录后按账号隔离；当前未接云同步，切换设备不会自动出现；
- **绝不写入** `tasks`、`projects`、`daily_reviews_v2` 或旧知识入口；
- 首次打开只加载示例，不把默认数据自动写入；
- 数据格式损坏或读取失败时**禁止保存**，避免覆盖用户已有数据；
- 添加、编辑、排序、开关采用先生成草稿、存储成功后才刷新视图；不提供删除历史或重置按钮；
- JSON 备份可以下载，但 **V1 不含导入恢复功能**，导入计划在用户确认后单独实现；
- 默认节点里的信息链和数据字段是学习占位，均标「待核实」；**没有实际接入 OMS/TMS/EDI/轨迹或数据库**。

## 验收
运行已有项目环境 `npm run dev`，另开终端：

```bash
TEST_ORIGIN=http://127.0.0.1:8765 node tests/logistics-knowledge-ui.mjs
```

检查工具区导航、直达链接、模块配置、节点增改、保存刷新、数据关联、JSON 下载、手机宽度、现有项目/任务/复盘不变。
