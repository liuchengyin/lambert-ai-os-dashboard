# 物流知识库 V3.5 · XMind 式微型分支、干线三路与独立基础资料工具

## 产品规则
1. **业务流程图只展示业务操作关系**：主线操作保留原尺寸及原顺序，每个操作边缘一个小“＋”（锁定时禁用）；点击后选择普通分支或异常流程。选择后可新建子操作或选择现有目标操作。子流程是独立小卡片，宽约 90–96px，普通分支蓝色实线、异常红色虚线。子操作旁也有“＋”，支持继续新增下级子流程。
2. **主线、分支、异常是业务路径**。业务节点中的“信息交换”独立保存 source / target / message / note，用于将来研究 OMS/TMS/EDI 时序，不改动 `module.branches`，不在主线添加信息步骤。节点详情允许添加与移除信息交换。
3. **干线大模块 = 陆运 / 空运 / 海运三个子线路**：画布显示唯一的「干线 · 三条运输线」父容器，内部三个并排运输线路泳道；旧 `linehaul` 陆运模块直接归入陆运泳道，空运/海运没有模块时显示“＋ 新建”，不强制自动写入用户知识数据。创建后分别显示在相应泳道；全链路 A/B 发布版同样使用三路分组。
4. **基础资料配置不是物流业务节点**。新增独立「基础资料配置」Tab：以大模块和各子环节为配置单元，展示各阶段真实填写的机场、航线、航班、板型、车队、线路、说明或关联记录；从独立工具里编辑。业务操作画布仅保留小尺寸的「基础资料 X 项」入口以免干扰主线，取消重复的配置按钮和阶段分支按钮。已有 V3.4 前置配置原数据 `prerequisites` 无损继续使用，不做大规模迁移。
5. **权限、存储和用户历史不变**：继续默认加锁/草稿/确认发布/历史回滚。沿用已有单一版本本地记录 `lambert_logistics_versions_v1`，不覆盖旧 V1 数据键，不变更其他 OS 项目、任务、复盘或链接。
6. **范围边界**：尚未导入真实事件码/轨迹码表，不创建假码映射；基础资料暂按模块/子环节保存，未来再提供跨线路可复用的配置模板与系统接口；复杂时序图的可视化绘制仍保留为后续改进。

## 技术
- `logistics-v35-model.js` 纯函数：运输线路分组、有限深度分支树与防循环、旧数据重复 edge 去重、独立信息交换增删。
- `logistics-stage-view.js`：删除“＋ 分支 / 异常”阶段按钮，主操作加一个微型 + 和两类型菜单，子路径递归渲染尺寸缩小。任意分支节点可继续添加子流程。
- `logistics-knowledge-v1.js`：分支对话框由小＋预选择流程类型；独立基础资料工具及独立信息交换弹窗，所有更改都只进入草稿。
- `logistics-overview.js`：修复 V3.4 运输类型变量与全链路 A/B `mode` 遮蔽的问题；正确显示纯宏观 A 模式，已发布 B 模式保留操作展开；干线汇入三路分组。
- `logistics-v35.css`：微型路径卡片、红蓝语义标记、淡紫主题三泳道与配置工具。
