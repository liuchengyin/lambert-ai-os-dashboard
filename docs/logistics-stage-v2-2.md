# Lambert Logistics · 四层业务积木 V2.2

## 来自业务图的结构调整
用户提供「国内中心仓」收发流程：主业务分类为仓/干/关/配；业务模块为国内中心仓等；子环节为到车、收入、分拣、发出；最小单元为到车扫描、换单打印、收入操作、安检扫描、称重复核、批次创建、上车扫描、发车扫描等。

### 四层树（不是硬编码的执行顺序）
- L1 类别：仓、干、关、配（展示分类，允许同一类别在一条路线重复出现）
- L2 业务模块：国内中心仓、陆运干线、进口关务等，可重排、启停、折叠
- L3 业务子环节：到车、收入、分拣、发出，可创建、改名、重排、折叠；横向虚线框视觉表现
- L4 操作节点：可创建、修改、重排、跨子环节移动、跨模块移动，保留已有触发信息、数据字段和核实证据

示范链路：`仓 → 国内中心仓 → 到车（到车扫描/下车扫描） → 收入（换单打印/收入操作/安检扫描/异常上报） → 分拣（称重复核/打印包签/建包扫描/大包复核/批次创建/绑定） → 发出（创建车签/打印车签/上车扫描/发车扫描）`。**该示例用于结构学习，并非确认实际 SOP 顺序。**

## 数据存储与 V1 兼容
仍使用 `lambert_logistics_knowledge_v1` 与 `schema:1`，未创建新数据键。每个模块**可选** `stages:[{id,name,collapsed}]`，每个操作**可选** `stageId`。原来的 `nodes` 继续是一维数组，其原始信息、数据与未来未知字段均保留。读取 V1 没有 stages 的模块时，界面虚拟显示「操作流程」组，**不会因浏览自动写入/转换**。用户首次添加子环节时才增加通用原有操作组，原节点继续归属它。

## 交互
- 大模块、子环节、操作节点都有拖拽入口；远距离或移动端优先使用顺序箭头/详情的模块＋子环节选择器。
- 只移动位置与 stageId，不重写 operation 字段。
- 原大模块 HTML5 拖拽与原数据 Tab 都保留。
- 按需展开信息流/数据流，不在主画布强制展示接口或事件码。
- 业务内容来自用户提供的流程图，仅作为需要验证的研究模板；不宣称已连接 OMS/TMS/EDI。
