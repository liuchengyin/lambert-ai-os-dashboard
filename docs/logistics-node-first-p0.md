# Lambert Logistics · P0 单节点研究闭环 / 数据完整性审查（2026-10-29）

## 产品目标（不等于业务事实）
先研究一个操作节点：何时开始 → 谁或哪个系统执行 → 操作对象及输入 → 具体怎么做 → 操作结束产生什么 → 正常或条件分支／异常 → 上游和下游的关系。所有流程图上的相邻操作仅代表当前排列，不能自动定义真实业务依赖、EDI 信息传输或轨迹 SLA。

## 本轮 P0，范围限定物流知识库
1. **节点内容完整**：补充可选 `entryCondition`（开始条件）、`executor`（操作角色或系统）、`operationInput`（所需输入）、`researchBasis`（研究来源/待核实），编辑后不丢旧 `evidence/information/data`、触发项、Event/OperationCode、未知字段。空字段应明确显示“待核实”，不能自动声称已确认。
2. **关系不误导**：节点详情分开展示「同一子环节正常显示顺序（未核实）」与「已记录的进入/离开分支（异常或条件）」。每条入/出分支可以打开相关节点；只输出本模块已存在的显式边，不从操作数组推断接口或系统状态。跨模块关系缺失就标明未核实。
3. **防止隐藏连线**：带有 incoming/outgoing branch 的节点禁止直接跨大模块移动，否则旧模块中的 branch 会变成孤儿、画布不再显示。数据不改并明确告警；同模块重排及其他无关联跨模块移动保持可用。
4. **回归与数据保护**：新增纯模型与 Chromium 用例，保证只影响物流模块，旧 schema:1 与 `lambert_logistics_knowledge_v1` 原数据键只读，`lambert_logistics_versions_v1` 仍仅在明确保存/发布后写入；原节点 ID、未知字段和发布快照不变。
