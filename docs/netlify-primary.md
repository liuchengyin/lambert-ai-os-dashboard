# Netlify 作为主要工作台入口

用户在 2026-11-01 明确 Netlify 是主要工作台之一。Vercel 与 Netlify 由同一仓库 main 构建，发布后分别记录部署提交与功能验收，不能只验证 Vercel 就称双站发布完成。

## 本次修复

复用尚未合并的 PR #100 的资源审计、私有目录隔离、公开账号配置 Function 和对应测试，保留原分支不修改。在最新 main 上补入 `reading-pdf-viewer.mjs` 等现有阅读资源，保留后续的书架、阅读模式、阅读高度、壁纸改动。

原正式构建漏掉启动列表中的 `lib/link-recovery.js`，导致启动中断。本次构建若再缺少字面依赖会直接失败，避免产出成功但网页打不开。静态文件与服务器 Function 分开部署；不改变站点 Private/访问保护，不清理浏览器数据，不迁移或修改生产数据库。

## 功能边界

- 网页静态功能与阅读资源：纳入实际 Netlify 构建产物的启动和阅读回归。
- 邮箱登录公开配置：复用已有验证器，优先使用平台公开配置，未配置时只从固定的 Vercel 公开配置端点读取；用户登录和数据仍直连原 Supabase，按已有账号权限访问。
- 两个域名的 localStorage、IndexedDB 与登录会话不共享；任务、项目、复盘、文档和书架只有已云端保存的内容可在同账号下拉取。
- AI、飞书归档和自动识别链接的服务端 API 尚未迁移，此时 Netlify 仍不是全部后端能力等同的版本；其请求继续明确返回不可用，不代理付费写入接口。
- 真实 Netlify 登录、注册邮件/找回密码回调和用户网络可达性必须另行实测；模拟双来源测试不代表真实跨站验收。

## 发布验收

通过 PR 合并到 main 后，由各自平台 Git 集成自动构建。核对 Netlify 构建命令来自 netlify.toml、发布目录为 netlify-dist、生产分支为 main，并分别记录两站提交和启动/账户配置状态。对受保护站点不关闭访问保护、不创建公开分享链接来冒充匿名可达。

原 PR #100 的部署配置和账号实现已有历史验证，本次采用其修复但不合并该草稿 PR；后续可由该 PR 的负责人确认关闭或继续承载额外诊断工作。
